# NetaBoard

Election predictions, promise tracking, and coalition math for Indian politics —
built like a live scoreboard, not a news feed. Next.js 14 (App Router) + Supabase,
deployable free on Vercel.

Already verified: `npm run build` compiles clean, all 19 pages return 200, and every
API route degrades to a clear "demo mode" message when its keys aren't set yet — so
you can deploy this today and wire up real data at your own pace.

demo data (`lib/fallback.js`) when it isn't — so the whole site is browsable the
moment you deploy it, before you've touched the database.

## 1. Set up Supabase (free)

1. Create a project at [supabase.com](https://supabase.com) — free tier.
2. Go to **SQL Editor** → paste in `supabase/schema.sql` → run it.
3. Paste in `supabase/seed.sql` → run it. This loads the Bihar 2026 example data
   (real 2020 assembly seat counts, sample politicians/promises, etc).
4. Go to **Project Settings → API** and copy:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (**server-only, never expose this**)

## 2. Get free API keys

Configure as many as you want — every gateway (`lib/ai.js`, `lib/news.js`,
`lib/social.js`) is built to use whatever you've set and skip whatever you
haven't, no code changes required either way.

### AI providers (`lib/ai.js` tries these in order, falls through automatically)
| Provider | Get a key | Why it's here |
|---|---|---|
| **Groq** | [console.groq.com](https://console.groq.com) | Free, no card, fastest inference (LPU hardware) — first choice for chat/fact-check |
| **Gemini** | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) | Free tier, strong general quality — second choice |
| **OpenRouter** | [openrouter.ai/keys](https://openrouter.ai/keys) | Aggregates many `:free`-suffixed open models — last-resort fallback if the other two are rate-limited |

If Groq is rate-limited or down, the code automatically retries with Gemini,
then OpenRouter — that's the "rotation" at work: redundancy across providers,
not a way to dodge any single provider's quota.

### News sources (`lib/news.js` — daily brief pulls from every one configured, deduped)
| Source | Get a key | Free tier |
|---|---|---|
| **GNews** | [gnews.io](https://gnews.io) | ~100 requests/day |
| **NewsData.io** | [newsdata.io](https://newsdata.io) | ~200 requests/day |
| **Currents API** | [currentsapi.services](https://currentsapi.services) | ~600 requests/day |
| **The Guardian Open Platform** | [open-platform.theguardian.com](https://open-platform.theguardian.com) | Free, generous — no hard daily cap for developer tier |

### Social / mention-volume sources (`lib/social.js` — drives the Political Stock Market)
| Source | Get access | Notes |
|---|---|---|
| **Reddit** | Free OAuth "script" app at [reddit.com/prefs/apps](https://www.reddit.com/prefs/apps) | Search API, mention counts over last 24h |
| **Bluesky** | Free account + App Password (bsky.app → Settings → App Passwords) | Public feed reads need *no* auth; keyword search needs this login |
| **Mastodon** | No key — just point `MASTODON_INSTANCE` at any instance | Public hashtag timelines are open by default on most instances |
| **Hacker News** | No key needed | Algolia's free HN search API — low volume for Indian politics, but zero cost to include |
| **X (Twitter)** | Optional, paid only | See note below |

### A note on X (Twitter)
You asked for X specifically. As of **February 2026, X discontinued free
developer API access entirely** — it's pay-per-use credits now, with no free
allowance for new developers. There's no way around that from X's side.
`lib/social.js` includes an `fromX()` function that's fully wired and ready —
it just stays at zero unless you set `X_BEARER_TOKEN`, which only works if
you've bought credits at developer.x.com. Until then, **Bluesky is the closest
free equivalent**: it's built on the open AT Protocol, has crossed 40M+ users
in 2026, and its public API needs no auth at all for feed reads (a free App
Password unlocks keyword search).

### On "multiple keys" and rotation
`lib/keyRotation.js` supports comma-separating multiple keys for one provider
(`GROQ_API_KEY=key1,key2`) and picks one at random per request — useful if you
legitimately hold more than one key (e.g. a personal key and a team key).
Worth being upfront: most providers' free tiers are tied to your *account*,
not the key itself, and their terms of service (Groq's explicitly) prohibit
creating multiple accounts purely to stack free quota. The rotation that
actually matters here is the one across *different providers* in `lib/ai.js`
— that's genuine redundancy, not a workaround.

## 3. Configure environment variables

Copy `.env.example` to `.env.local` for local dev, and add the same variables in
**Vercel → Project → Settings → Environment Variables** for production.

See `.env.example` for the full, commented list (Supabase, three AI providers,
four news sources, four social sources, plus `CRON_SECRET`). None are required
for the site to run — set only what you have, in any combination.

## 4. Deploy to Vercel (free)

```bash
npm install -g vercel
vercel login
vercel          # first deploy, follow the prompts
vercel --prod   # promote to production
```

Or push this folder to a GitHub repo and click **Import Project** on
[vercel.com/new](https://vercel.com/new) — Vercel auto-detects Next.js, no config needed.

`vercel.json` already defines two scheduled jobs:
- `/api/daily-brief` — once a day at 01:30 UTC
- `/api/stock-refresh` — every 6 hours

Vercel automatically sends `Authorization: Bearer $CRON_SECRET` on these requests,
which is what the routes check for — just make sure `CRON_SECRET` is set in your
Vercel project env vars. (Cron jobs run on Vercel's Hobby plan too, just capped to
once a day per job on Hobby — upgrade to Pro if you want the 6-hourly stock refresh.)

## 5. Local development

```bash
npm install
npm run dev
```

Visit `http://localhost:3000`. Without any env vars set, every page still renders
with realistic demo data — good for checking the design before wiring up Supabase.

```
app/
  page.js                 → home
  predictions/             → Election Prediction Hub
  market/                  → Crowd Prediction Market
  coalition/                → Coalition Builder
  politicians/[slug]/       → Promise Tracker + Political Timeline
  constituencies/            → Constituency Dashboard
  stock-market/               → Political Stock Market
  brief/                       → Daily AI Brief
  ask/                          → Ask Politics AI chat
  fact-check/                    → AI Fact Check
  calendar/, heatmap/, debate/, quiz/, manifesto/, history/, memes/, more/
  api/                            → route handlers (ask, fact-check, vote, daily-brief, stock-refresh, debate)
lib/
  supabaseClient.js   → browser client (anon key)
  supabaseServer.js   → server client (service role key — server only)
  data.js             → all server-side data fetchers, with fallbacks
  fallback.js         → static demo data
  ai.js               → unified AI gateway — Groq → Gemini → OpenRouter fallback
  news.js             → multi-source news aggregator — GNews, NewsData, Currents, Guardian
  social.js           → mention-volume aggregator — Reddit, Bluesky, Mastodon, HN, (X if paid)
  keyRotation.js       → picks a key at random from a comma-separated env var
components/           → shared UI (Gauge, VoteWidget, CoalitionBuilder, etc.)
supabase/
  schema.sql          → full DB schema + RLS policies
  seed.sql            → demo data
```

## Extending it further

- **Real geographic heat map**: swap `/app/heatmap/page.js`'s grid for
  [react-leaflet](https://react-leaflet.js.org/) + OpenStreetMap tiles, plotting
  each constituency by lat/long instead of a CSS grid.
- **Real leaderboard scoring**: once an election result is entered, write a
  Supabase function that compares `market_votes` against the outcome and updates
  `predictors.accuracy_pct`.
- **Auth**: add Supabase Auth (`@supabase/auth-helpers-nextjs`) if you want the
  leaderboard tied to real accounts instead of anonymous fingerprints.
- **Legal note**: several Indian states restrict publishing opinion/exit poll
  data during specific pre-election windows (Section 126A, Representation of the
  People Act). Check current Election Commission guidance before your prediction
  features go live around an actual election date.
